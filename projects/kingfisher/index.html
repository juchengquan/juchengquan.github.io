Kingfisher

A Python library for LLM agents that builds a fresh agent for every request, from only the tools, skills and data its caller is allowed to use.

PythonAgentic AILLMAccess Control
Source on GitHubLast updated November 2026

What it does

Give an agent a database, a shell and other agents to hand work to, and the hard question becomes who gets to use which. Most frameworks answer it once, in code, and every user gets the same agent.

Kingfisher answers it per request. Agents, tools, skills and subagents are plain files in a definitions folder, and some carry a lock naming who may reach them. When a request comes in, kingfisher builds the agent from only what that caller can reach. Anything locked away is left out rather than refused, so the model never learns it exists, and two people asking the same agent can get two different agents.

Also in the box

Every tool result kept

What a turn's tools returned is filed in the session's /records under an id like A-0042, so a long result can be read back later instead of held in the conversation.

Memory

At the end of a turn a memory writer tidies what the session remembers. With a store wired in, a user's memory follows them into new sessions.

Swap the parts

Sessions, run events, instructions and wire formats are plugins: kingfisher ships one of each, and a deployment can bring its own.

Any model endpoint

It runs on deepagents and speaks to Anthropic and OpenAI endpoints out of the box; any other is one registered wire format away.
